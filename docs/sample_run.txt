Root Cause Hypothesis

The deployment of search-v42 introduced a connection pool issue in the search service, likely due to:

    Connection leaks - Connections not being properly returned to the pool
    Incorrect pool sizing - Pool configured too small for the new load pattern
    Leaked connections from previous versions - Cleanup from old code running

This caused the search service to exhaust its database connections, leading to cascading failures:

    → Failed DB connection attempts
    → Elevated timeouts calling downstream services (payment-service)
    → Exponential latency growth

PostgreSQL itself shows no errors, so the issue lies specifically in the search service's connection management and not in the database infrastructure.
